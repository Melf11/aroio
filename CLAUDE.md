# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

The from-scratch rebuild of AroioOS (ABACUS electronics audio streamer, Raspberry Pi 3B/4/5, all Aroio models SU/EX/LT + plain Pi). The old system lives in `../aroio-ng` and must not be modified. Plan, decisions and open questions: `docs/NEUBAU-PLAN.md`. UI text and docs are German; code and comments are English.

## Commands

```
./dev.sh                 # aroiod (simulated hardware, port 8140) + Vite (5173); simulator at /sim.html
./dev.sh test            # pytest + svelte-check (fails on a11y warnings) + vite build + i18n check
./dev.sh build           # build web/dist and serve it from aroiod on :8140 (/sim)
./dev.sh reset           # wipe the simulated device (.dev/)
.venv/bin/python -m pytest tests/test_roomcorr.py::test_level_and_time_alignment   # one backend test
cd web && npx playwright test -g "Raumkorrektur" --project=mobil                     # one e2e test
make e2e                 # Playwright flows + axe (WCAG 2.2 AA), mobile 375×812 and desktop 1280×800
node tools/i18n-check.mjs --list   # German UI texts without English translation
make docker-image AROIO_PROFILE=generic   # SD card image in Docker -> output/aroio-sdcard.img (hours on first run)
make selftest            # image checks without hardware (after docker-image)
./dev.sh deploy          # aroiod + app to a real device (AROIO_HOST, default aroio.local); --bundle = whole system via RAUC
docker run --rm -v "$PWD":/work -v aroio-build:/build -w /work aroio-build tools/br-checkconfig.sh
                                          # lists defconfig symbols Buildroot silently dropped (run after every defconfig change)
```

## Architecture

- **aroiod/** (Python, aiohttp) is the single control process and the only writer of `/data`. `engine.Device` holds all logic (source switching, volume, sample-rate following, DSP presets, services, migration). Everything outside the process goes through `device.world`: `sim.SimWorld` in development, `real.RealWorld` on the Pi; both implement the same methods (a test for one usually needs the other).
- **State flow**: `hub.Hub` holds topics (`player`, `dsp`, `services`, `roomcorr`, `sim`, …); `Device.publish_*` replace a topic as a whole and push it over `/api/v1/ws`. The app never polls. REST (`web.py`, `/api/v1`) only sends commands; errors are JSON `{error, field}` with text meant for end users.
- **Config**: `config.py` declares a schema (`SCHEMA`, `F`), every change is a validated patch written atomically (`store.atomic_write_json`); unknown keys are rejected. Schema changes need a version bump and an entry in `UPGRADES`. Secrets (passwords, tokens) live separately in `secrets.json` (0600) and are never sent to the app. `/boot/userconfig.txt` of the old system is only read by `migration.py`.
- **Audio path**: exactly one source plays; a new source pauses the previous one (no mixer, so no forced rate). On the device every player writes to `plughw:Loopback,0,0`; CamillaDSP releases its end when nothing plays (`stop_on_inactive`) and `real.LoopbackWatch` restarts it with the rate *and sample format* the next player opened the loopback with (`/proc/asound/Loopback/pcm0p/sub*/hw_params`). Never set the CamillaDSP rate from player announcements on the device (`world.rate_from_loopback`): the loopback refuses a second rate and CamillaDSP stops silently. `pause_source` makes the previous player let go (AVRCP pause, or restarting shairport-sync/librespot/squeezelite). `dsp.camilla_config()` turns a preset into a CamillaDSP 3 config for the current source rate; FIR presets carry one file pair per rate, missing rates fall back to the nearest rate of the same family with resampling. Empty pipeline = bit-perfect. The M/S "Cleaner" matrix matches the old BruteFIR config.
- **Room correction**: `roomcorr.py` is pure maths in numpy (no scipy: own FFT convolution and bounded Levenberg-Marquardt) (sweep, deconvolution, smoothing, target curves, PEQ fit with hard +3 dB total boost limit and no boost below the speaker roll-off); `wizard.RoomWizard` is the step state machine (topic `roomcorr`), A/B via a temporary `preview` preset. `SimRoom` provides a deterministic room for tests and the simulator.
- **Library**: `library.py` defines one browse model (`page`/`item`, ids `provider:kind:key`) for own music, TIDAL, Qobuz and radio. `SimLibrary` is fake data; the Lyrion JSON-RPC mapping (phase 4) must produce the same shapes.
- **Simulator audio**: `web/src/sim/audio.js` plays sound on the dev machine. It rebuilds the CamillaDSP config from the `sim` topic in Web Audio, synthesises music per track and optionally applies the simulated room (`SimRoom.MODES`). `SimWorld.mic_mode` is `sim` (virtual room, default for `./dev.sh`), `none` (tests) or `host`: then `measure()`/`level_check()` send a request via the `sim` topic and wait until the simulator page plays/records and posts to `/api/v1/sim/result/{id}`. The page auto-selects a UMIK on the host.
- **Network setup** (`netsetup.py`, same logic in simulator and device): without cable and WLAN after a grace period the world opens an open hotspot `Aroio-Einrichtung-XXXX` (device: hostapd + dnsmasq units `aroio-hotspot`/`aroio-portal-dns`, configs written to `/run/aroio`, iwd stopped meanwhile). The `captive` middleware in `web.py` redirects foreign hosts and OS probe URLs to `http://192.168.4.1/einrichtung` (`views/WifiSetup.svelte`). Connecting from the hotspot answers first (`switching: true`), then switches; on failure the hotspot returns with `network.setup.error`. Known WLANs persist via `/var/lib/iwd -> /data/iwd`. In the simulator a password starting with "falsch" or shorter than 8 characters fails.
- **Outside sources on the device** report to aroiod: AirPlay through the shairport-sync metadata pipe (`airplay_meta.py`: start/stop, title, cover served at `/api/v1/cover/airplay`, iPhone volume), Bluetooth by polling BlueALSA/BlueZ (`bt_watch.py`, AVRCP track and volume), Spotify through librespot `--onevent` → `/usr/lib/aroio/spotify-event` → `POST /api/v1/internal/source`. Phone volume changes the Aroio volume (`Device.remote_volume`); players themselves never attenuate. All player units take the device name from `/data/aroio/names.env` (written by `RealWorld.rename`).
- **Controls**: `inputs.py` reads evdev (IR scancodes via rc-core, rotary encoder, gpio keys; BlueZ `(AVRCP)` devices are ignored). `hardware.ir_map` maps scancodes to actions (Aroio RC5 remote preset, learning via `/hardware/ir/learn`). Model, IR, encoder and display rotation become `aroio.txt` lines via `models.boot_lines()` (reboot needed).
- **App password** (`auth.py`): optional, scrypt hash + session cookies in `secrets.json`; the `auth` middleware guards `/api/` except `/api/v1/auth/` and localhost-only `/api/v1/internal/`. The app checks `/auth/status` before opening the WebSocket and shows `views/Login.svelte`.
- **Factory filters**: BBC-Dip and Echo from AroioOS 5.1 (`aroiod/factory/filter.tgz`, right channels are symlinks) are built-in presets `werk-*` read from `/usr/share/aroio/filters` (dev: unpacked into the data dir); they cannot be deleted.
- **Level meter**: `levels.py` polls `world.levels()` (CamillaDSP `GetSignalLevelsSinceLast`, playback side) 15×/s only while a client is connected to `/api/v1/levels`; the app shares one socket (`lib/levels.svelte.js`, `components/LevelMeter.svelte`).
- **Device services that Buildroot does not ship as systemd units** (shairport-sync, nqptp, squeezelite, Spotify Soloist as `aroio-soloist` + `aroio-pulse`, info screen, `aroio-grow-data`) have own units in the overlay; aroiod starts/stops player units at runtime to match `sources.*.enabled` (never `systemctl enable`: the root is read-only); `tools/image-selftest.sh` fails on any enabled unit whose file is missing. iwd and bluetoothd keep state on `/data` via `BindPaths` drop-ins (they run with `ProtectSystem=strict`).
- **web/** (Svelte 5 runes, Vite, no router library): `lib/state.svelte.js` (WebSocket topics), `lib/router.svelte.js` (History API, focuses `main h1` after navigation), `lib/i18n.svelte.js` (German text is the key, `lib/en.js` maps it; `'Hell|Darstellung'` adds a context). Views in `src/views`, settings pages in `src/views/settings`, simulator in `src/sim` (separate entry `sim.html`, not shipped in the image).
- **aroiod/real.py**: the world on the Pi (`python -m aroiod` without `--sim`): CamillaDSP websocket client (re-sends update interval/config/volume on reconnect, polls state), `LoopbackWatch` (rate/format following, see Audio path), DAC/UMIK detection from `/proc/asound/cards`, test tone and measurements via `aplay`/`arecord` into `hw:Loopback,0,0`. Hooks report through `POST /api/v1/internal/source` (localhost only; events start/stop/meta/volume). Changes go to a running device with `./dev.sh deploy` (`/data/dev`, used by `/usr/lib/aroio/aroio-python` only while `/data/dev/base` equals `/etc/aroio-version`, so an update switches it off). Methods not implemented yet raise `ValueError` with a German "folgt in Phase 1" text.
- **br2-external/**: Buildroot external tree (aarch64, squashfs A/B + RAUC, `data` partition); Buildroot 2026.02.3 itself is fetched unmodified. Kernel: raspberrypi/linux rpi-6.18.y pinned commit; with a custom kernel tarball the header version must be declared (`BR2_PACKAGE_HOST_LINUX_HEADERS_CUSTOM_6_18`), otherwise glibc and everything depending on it is silently dropped. DAC overlays come from `board/rpi/profiles/<AROIO_PROFILE>.txt` (copied to `aroio.txt` on the boot partition). Build output must stay in the Docker volume (macOS is case-insensitive).
- **Spotify**: Spotify Soloist (Spotify's own player; librespot is gone, it gets no audio keys for many accounts). Not in the image: the user's Soloist key (Einstellungen › Dienste › Spotify) goes to `/data/aroio/soloist.env`, `aroiod/soloist.py` downloads the player to `/data/spotify/bin` and updates it (`aroio-soloist-update.timer`, builds expire after 90 days, exit 10 → `OnFailure`). It plays through a minimal system PulseAudio (`aroio-pulse.service`, `/etc/aroio/pulse.pa`: one sink into the loopback, suspend after 1 s). `SoloistClient` talks to its WebSocket on 127.0.0.1:9090 (state, track, cover, play/pause/next/previous/seek).
- **Versions**: Buildroot version in the Makefile (`BR_VERSION`); packages that are behind upstream even there get version bumps as patches in `br2-external/buildroot-patches/` (applied after the clone; another version or other patches fetch Buildroot again).
- **Updates and A/B boot**: `updates.py` picks a GitHub release of `Melf11/aroio` (stable = no pre-release, beta = any; bundle asset `*.raucb`; notes = bullet lines of the release text); `RealWorld.install_update` downloads to `/data/update` and runs `rauc install`; `Device._update_loop` checks daily and installs at night with `update.auto` (release builds only). The boot partition holds firmware, `config.txt`, `aroio.txt` and `slot-a/`/`slot-b/` (kernel, DTBs, overlays, `cmdline.txt` with `rauc.slot=`), selected by `os_prefix=` in `config.txt`. Each rootfs carries its boot files in `/usr/share/aroio/boot`; the RAUC backend `/usr/lib/aroio/rauc-tryboot` copies them on `set-primary`, uses `tryboot.txt` + `/usr/lib/aroio/reboot` ("0 tryboot") on Pi 4/5 and switches `config.txt` only on mark-good; `aroio-trial-watch` reverts after 5 min (also the only fallback on Pi 3). Keyring: release cert from the repo (+ dev cert in dev images). CI: `.github/workflows/release.yml`, started by hand (workflow_dispatch: version, notes separated by `;`; empty version = test build); a GitHub-hosted job hands over after 5 h (`tools/ci-prune-out.sh`, state cache per commit, dispatches the next part); secret `RAUC_KEY`, optional variable `AROIO_RUNNER`.
- **NetJack** (`netjack.py`, unit `aroio-netjack`, off by default): jackd on the dummy driver + `netmanager` (the Aroio is the master); only while a computer is connected the `audioadapter` internal client opens the loopback. Pausing = SIGUSR1 (adapter closed until that computer disconnects). libjack via ctypes (jack2 has no jack_load/jack_lsp any more).
- **CamillaDSP** is 4.0.1 (config format of 4.x: `S32_LE`, `F64_LE`, resampler profile `Accurate`). Upstream ships no Cargo.lock, so `tools/vendor-camilladsp.sh` builds the vendored archive from `br2-external/package/camilladsp/Cargo.lock.<version>` (run automatically by `make image`). 4.1.x (NEON FIR) needs Rust >= 1.90; Buildroot 2026.02 has 1.88.

## Rules that are easy to break

- Accessibility is a gate: `svelte-check --fail-on-warnings` and the axe tests must stay clean. Use real controls (`button`, `a`, native range/radio), visible labels, `aria-live` via `announce()`/`toast()`, touch targets ≥ 44 px, no information by colour alone.
- Brand colour `#00AAAA` (`--brand`) is only for fills with `--on-brand` text; text in brand colour uses `--brand-ink`. Define colours as tokens in `src/app.css` for light and dark.
- Svelte trims leading whitespace in `{#if}` blocks: write separators as `{' · '}`.
- Every new UI text needs an English entry in `web/src/lib/en.js` (`./dev.sh test` reports missing ones).
- Backend changes that affect the app need a test in `tests/test_api.py`; flows a person goes through need a Playwright test.
